# ECMA-402 implementation map

This maps each numbered step, nested step, assertion, and numbered note of the
operations used by `Intl.getCanonicalLocales`. Step numbers follow ECMA-402
revision [`3691634ebc17`](https://github.com/tc39/ecma402/commit/3691634ebc1794f2af74cb26e59824b21090c3ad); every
step link targets its immutable source line. The Rust parser fuses several
abstract operations instead of constructing their intermediate spec records.

The implementation uses these pinned inputs:

- [ECMA-262 `40ce6f206b56`](https://github.com/tc39/ecma262/commit/40ce6f206b5669e69bf010a38267ae24a2843404) for JS conversions, property operations, arrays, and function shape.
- [CLDR 48.2 `11299982335b`](https://github.com/unicode-org/cldr/tree/11299982335beb974c1c63c45265184e759c0f41) for generated language/territory, Unicode/transformed, and subdivision aliases.
- [ICU4X `icu_locale` 2.3.1 source `898d79c69f37`](https://github.com/unicode-org/icu4x/blob/898d79c69f37da7b45a15a5714663c9b59b3d928/components/locale/src/canonicalizer.rs) for canonicalization and likely-subtag selection. `Cargo.lock` pins its data-crate dependencies separately.
- [Test262 `419d3e0a2273`](https://github.com/tc39/test262/tree/419d3e0a2273ba01a3bfcbec423f2801425b8e93/test/intl402/Intl/getCanonicalLocales) for the complete 38-file API suite; `tools/hermes-test262` runs default and strict scenarios, 76 executions.

```mermaid
flowchart TD
    A["Intl.getCanonicalLocales"] --> B["JS: list coercion, iteration, errors, deduplication"]
    B --> C["C++ JSI host function and C ABI"]
    C --> differential tests["Rust: validate and canonicalize each tag"]
    differential tests --> E["ICU4X language and likely-subtag data"]
    differential tests --> F["Generated CLDR compatibility tables"]
```

## Native and provider contracts

`installCanonicalLocales(runtime)` creates a private JSI host callback and passes
it into the wrapper closure. Every present input string makes one synchronous
JSI/C ABI call. JSI copies input to UTF-8; Rust returns owned bytes; JSI creates
a JS string before the C++ guard frees those bytes. Invalid tags use status 1
and become the RangeError required by locale-list step 7.c.v. Defensive ABI
input/panic failures become JS errors; these are not additional locale grammar
rules. Rust allocation failure may abort.

`Canonicalizer::try_new_with_provider` loads four global ICU payloads once.
Instances retain their payloads after the provider is dropped. provider tests tests cover
missing markers, retention, Send + Sync, and isolation between different
provider data. `compiled_data` is optional for Rust callers. Generated CLDR
language, territory, extension, and subdivision tables remain compiled;
provider mode does not promise a zero-data binary. The current Hermes C ABI
uses compiled data; injecting a provider into JSI is not implemented here.

JSI does not expose arbitrary ECMAScript internal slots. `localeString` therefore
captures the original trusted Intl.Locale.prototype.toString during installation
and uses its brand check instead of reading a user-overridden instance method.
Install after any trusted Locale implementation and before untrusted application
code. The host test runner first bootstraps canonicalization, loads the optional
JS Locale prelude, then reinstalls the wrapper to capture that implementation.
Only the Locale-object Test262 file needs this prelude. This tests compatibility
with the existing Locale polyfill; it does not establish native cross-realm
Locale coverage. Other arguments never look up the live Intl.Locale property.

The host runner builds pinned Hermes with platform Intl disabled so tests
exercise this implementation. Android/iOS distribution, native mobile profiling,
and upstream Hermes extension registration are outside this PR. The differential
suite explicitly records two existing JS baseline gaps (root and Armenian SU
territory selection); all timed benchmark inputs agree. No result is silently
replaced with a JS fallback.
