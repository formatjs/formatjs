# formatjs_java_printf_parser

Rust parser for [Java SE 17 Formatter](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Formatter.html) syntax, including Android's printf-style placeholders. No runtime dependencies. Requires Rust 1.90 or newer.

```toml
[dependencies]
formatjs_java_printf_parser = "0.1"
```

```rust
use formatjs_java_printf_parser::{parse, Element};

let elements = parse("Hello %2$s, %s %<s %%")?;
let indices: Vec<_> = elements.iter().filter_map(|element| match element {
    Element::Specifier(specifier) => specifier.argument.map(|argument| argument.index),
    Element::Literal(_) => None,
}).collect();
assert_eq!(indices, [2, 1, 1]);
# Ok::<(), formatjs_java_printf_parser::ParseError>(())
```

`parse(&str)` returns `Result<Vec<Element<'_>>, ParseError>`. Literal text, raw specifiers and flags borrow the input. Spans use UTF-8 byte offsets into that original input. Errors carry an `ErrorKind` and a span covering the offending specifier through the point where parsing failed.

Specifiers expose conversion kind, uppercase mode, explicit argument index, resolved argument reference, flags, width and precision. Resolved argument indices are one-based. Explicit indices do not advance the implicit counter. `<` reuses the previous consuming specifier, even when an explicit index is also present. Percent and newline conversions consume no argument and leave both counters unchanged. Their explicit index, if present, remains available in `argument_index`.

Supported syntax:

```text
%[argument_index$][flags][width][.precision]conversion
%[argument_index$][flags][width][tT]date_time_suffix
```

Includes Java's general, character, integer, floating-point and date/time conversions, plus `%%` and `%n`. Parsing checks conversion/suffix names, repeated and incompatible flags, required width, allowed precision and Java's signed 32-bit numeric bounds. `Conversion::DateTime(char)` preserves the suffix exactly; `uppercase` refers to the `T` prefix.

This is a parser, not a formatter or translation validator. Runtime argument counts, Java types and values are not checked. Some flags depend on runtime types: `%#s` requires `Formattable`; signed octal/hexadecimal flags require `BigInteger`. A successful parse does not guarantee that particular runtime arguments can be formatted.

XML, Android backslash escapes and braces remain literal text. Decode resource XML and respect `formatted="false"` before invoking the parser. Parse each plural or array item separately: argument indexing restarts for each independently formatted string. C printf length modifiers, `*` widths and iOS `%@` belong to different dialects and are rejected.

## Tests

```sh
bazel test //crates/java_printf_parser:java_printf_parser_test \
  //crates/java_printf_parser:java_conformance_test
```

Conformance fixtures are generated by the Bazel Java runtime using `java.util.Formatter`. The test compares syntax acceptance across conversions, flags, width, precision and indexing, then checks resolved argument selection against actual Java output. Java is a test dependency only.

The package is a Cargo workspace member. Release automation registration is separate.
