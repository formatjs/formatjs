## Authority and scope

Requested authority remains [ECMA-262](https://tc39.es/ecma262/). Its fetched snapshot has no Temporal API chapters. They supply comparison/navigation, not substituted authority or complete compliance signoff. This matrix covers every top-level operation/branch of that comparison, then names unresolved dependencies.

## Clock arithmetic and candidate selection proof

For valid projection, timeOf(current) is in [0,nsPerDay). Each permitted increment divides its unit's parent period. [plain-time.ts:299–303](../../packages/temporal/plain-time.ts#L299) removes an exact parent multiple, rounds the requested field and smaller fields, then restores larger fields. This matches separately published [comparison §4.5.16 RoundTime](https://tc39.es/proposal-temporal/#sec-temporal-roundtime): hour uses whole clock, minute uses minute through nanosecond, and each smaller unit similarly drops larger fields. [Comparison §5.5.11 RoundISODateTime](https://tc39.es/proposal-temporal/#sec-temporal-roundisodatetime) balances returned day carry. Those operations were independently re-read in official HTML for this review.

HalfEven uses the field-relative quotient, exactly as the comparison requires. Example: 01:10 rounded to 20 minutes with halfEven gives 01:00 (minute quotient 0.5), not01:20 from whole-day quotient 3.5. Do not claim parent-base decomposition preserves whole-day halfEven parity; parent/quantum may be odd. Current implementation correctly uses field-relative parity. No Number contains epoch or rounded nanoseconds. Epoch day is a bounded integer; conversion back to BigInt is exact.

For [offset resolver:305](../../packages/temporal/zoned-date-time.ts#L308), each candidate is an epoch instant corresponding to rounded local ISO fields. localTime−candidate is its exact offset. matchMinute=false permits only equality with original raw offset; otherwise compatible fallback implements preferred-offset failure. Raw representation preserves second/fraction offsets exactly. Old offsetText formatted all pieces as BigInt, so no lossy Number conversion is fixed or alleged.

## Snapshot/native timing bound

Old [offsetText:719](../../packages/temporal/zoned-date-time.ts#L710) first checked [zonedSnapshot:178](../../packages/temporal/zoned-date-time.ts#L179); installed native backend could return cached offset text without querying offset again. Thus “always preserves second offset query” would be too broad.

For stable built-in runtime configuration, changed TS branch cannot reach that snapshot route: nativeTemporal present at round934 causes immediate native return; absent nativeTemporal makes [zonedSnapshot:180](../../packages/temporal/zoned-date-time.ts#L181) return undefined. configureNativeTemporal constructs roundZonedDateTime wrapper unconditionally, with partial typed invoke falling back to query ([native.ts:868–880](../../packages/temporal/native.ts#L906)). With native absent, ordinary local projection queries offset201–207; old [offsetText:722](../../packages/temporal/zoned-date-time.ts#L713) and new [zoned-date-time.ts:976](../../packages/temporal/zoned-date-time.ts#L967) query original offset after clock rounding, before rounded ISO validation. Correction retains that query timing for this profile. Identity path still returns earlier.

No claim covers backend reconfiguration/reentrancy during provider callbacks, arbitrary experimental NativeQuery behavior, or tampered bootstrap exports. Those require adapter/provider contract analysis. Public option getters finish before native934 selection; configuring backend there selects the native route consistently. Original slot snapshots existing from earlier backend installations cannot make zonedSnapshot return cached data while nativeTemporal is absent.
