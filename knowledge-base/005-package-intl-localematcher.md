# @formatjs/intl-localematcher

## Purpose

Implements UTS #35 locale matching algorithms: Lookup matcher and BestFit matcher. Used by all Intl polyfills for `ResolveLocale`.

## ECMA-402 Conformance

- **Section 9.1** — `ResolveLocale` abstract operation
- **UTS #35 Section 4.4** — Language Matching (CLDR distance-based algorithm)

## Design Decisions

### ICU best-fit matching

The TS matcher and `crates/intl_localematcher` follow ICU4C/J 78 defaults:

- Language-first distances; one-way fallback rules stay directional.
- Exclusive threshold: default script distance (50 in CLDR 48).
- Requested-list demotion: distance from en-US to en-GB (5 in CLDR 48).
- Default supported locale, then paradigm locales, then input order.
- Exact maximized LSR lookup includes explicit-subtag flags. Zero-distance
  equivalents use ICU's three fractional bits; nonzero ties prefer likely subtags.
- Macroregions use the maximum distance across their region partitions.
- Bare `und`, private-use unknown locales, and pseudolocales stay isolated.

Lookup matching remains RFC 4647 prefix lookup.

### Performance

Canonical tags and maximized LSRs are memoized. Supported lists cache raw LSR
indexes, maximized indexes, and default/paradigm ordering. The public resolver
preserves array identity and reuses Set snapshots after checking their contents;
array and Set mutations invalidate cached best-fit matching state.
Set-backed resolution keeps a private validation buffer and frozen matcher
snapshot. Contents/order are checked once per call; the prepared matcher trusts
only factory-created snapshots, avoiding a second scan. Public frozen arrays
can contain changing getters and retain normal validation.
Lookup stays on the validation buffer and creates no best-fit snapshot.
See [constructor measurements](audits/2026-10-31-numberformat-constructor-snapshots.md).

Exact matches build the raw index only as far as the first match. Alias-free,
canonical LSR strings bypass native canonicalization using generated CLDR alias
metadata. Equivalent LSRs try all eight explicit-subtag subsets; the fast path
returns only when its distance beats every non-equivalent LSR's lower bound. Repeated non-exact matches
cache the closest supported locale; each supported-list cache holds at most 256
requests. The public path does not allocate diagnostic distance matrices.
The Rust matcher prepares supported locales once and uses a bounded, thread-safe
closest-match cache. A generated language index rejects impossible language
matches without scanning every supported locale. `DesiredLocale` prepares reusable
requests; `benchmarks/locale-matching` compares Rust with ICU4C and ICU4J.

Run existing public benchmarks with
`bazel run //packages/intl-localematcher/benchmark:bestfit_benchmark` and Rust with
`bazel run -c opt //crates/intl_localematcher:matcher_bench`. Keep cold/fresh-list
costs separate from warm repeated matches. Unit tests retain the #4936 timing
guards and cover the public API with hundreds of supported locales.

### Shared generated data and conformance

`packages/intl-localematcher/scripts/distance-gen.ts` compiles pinned
`cldr-core` languageMatching and territoryContainment into language/script tables
and region-partition matrices. TS consumes `@formatjs_generated/cldr.core/matching`;
Rust checks in `matching_generated.rs`, refreshed by
`bazel run //crates/intl_localematcher:distance` and checked by `:distance_test`.
The TS runtime no longer uses the manually copied languageMatching table.
The native `intl_locale` matcher now delegates to the same Rust matcher,
with a bounded per-thread supported-list cache. Native formatter registries own
`AvailableLocales` snapshots, retaining a prepared matcher after first use rather
than hashing the full list per call. Appending locale IDs invalidates that
snapshot's matcher; replacing a payload with the same IDs does not. Matching
order, thresholds and winning-request indices stay unchanged. Equivalent
snapshots share the bounded cache's thread-safe matcher records. After the first
nonexact request, a lazy raw-key index replaces linear exact-match scans; first
exact requests retain the cheap existing path. The index preserves first-match
variant ties and special-locale barriers. Its legacy generated tables
remain available to the existing data generator.

Both ports consume shared fixtures and a differential grid generated by pinned
ICU4J. The grid covers requested-list ordering, aliases, explicit subtags,
macroregions, unknown locales, and pseudolocales. ICU4X supplies Rust parsing,
canonicalization, and expansion; incomplete expansions receive ICU matching's
additional `und` fallback and region/script inheritance correction (for example,
`und-Latn-419` infers Spanish). TS uses the host or polyfilled Intl.Locale data, so
CLDR upgrades must rerun the oracle checks.

## Dependencies

`@formatjs/fast-memoize`

Locale matching extracts only the Unicode `u` extension. Private-use subtags
remain intact, including text resembling `u-co-phonebk`; trailing extensions
are preserved separately from Unicode keywords.

`CanonicalizeUValue` applies ASCII case normalization and generated CLDR Unicode
keyword/subdivision aliases before `ResolveLocale` matches option values. For
example, `calendar: "islamicc"` resolves to `islamic-civil`. Unknown values remain
available for normal unsupported-value fallback; inherited object properties
are never treated as aliases.
