## Changes

All four formatting methods recognize Temporal inputs through captured intrinsic
brand checks, including foreign-realm values. Type-specific formats use already-read
options. Plain values ignore the formatter's timezone; instants use it. Numeric
inputs retain TimeClip; Temporal values preserve exact nanoseconds and their wider
plain-date range. Range endpoints require matching Temporal types and compatible
calendars. `ZonedDateTime` remains rejected as the specification requires.

DateTimeFormat now implements all 16 calendars required by the approved
Intl Era/Month Code specification. Calendar-specific CLDR records supply eras,
month names, styles, and interval patterns. Hebrew leap months and Chinese/Dangi
related years, cyclic years, and leap-month labels remain distinct formatting fields.
Unicode calendar aliases resolve consistently across shared locale negotiation.
Combined supportedValuesOf calendar enumeration now passes with DateTimeFormat.

Calendar arithmetic uses the public `temporal-polyfill` function modules, bundled
into the published artifact. Generated ICU4X tables provide Chinese/Dangi dates
across the full supported date range and the official Umm al-Qura year table;
ICU4X civil-calendar fallback applies outside that table. Production conversion
does not delegate to native Intl.DateTimeFormat.

Missing time interval patterns get a time-only fallback before combining with the
shared date. Existing CLDR interval patterns retain precedence. Calendar interval
fallbacks preserve required year fields and requested month representation.

Focused checks cover native and npm Temporal inputs, historical and boundary
calendar conversions, poisoned native Intl, inherited discriminators, calendar
aliases, leap months, related years, range parts, package exports, declarations,
and generated locale registration. Gregorian formats, including their ISO alias,
parse on first use.

Legacy and grandfathered behavior remains outside the implementation goal, with
all 12 failures still counted. Portable JavaScript cannot recover arbitrary
foreign constructor realm intrinsics from hidden bound/proxy slots, or confer
native Locale internal slots on a polyfill object. Isolated supportedValuesOf
also encounters the host's older calendar list; combined installation passes.

The selected ECMA-402 main draft stores `[[PrimaryIdentifier]]` for named timezones;
the Temporal integration text expects `[[Identifier]]`. The eight alias-preservation
failures retain main-draft behavior. CLDR 48.2 uses U+202F where one Test262 assertion
expects ASCII space. Combined Locale exposes an empty nondefault English collation
list because the Collator data implements no such tailoring; it does not advertise
unimplemented `emoji` or `eor` support. These data choices are allowed by ECMA-402.
